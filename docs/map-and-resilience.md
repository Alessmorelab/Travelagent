# 行程地图与异常恢复

## 小程序操作

1. 在「我的 → 旅行服务」连接真实后端，开启新对话，例如请求武汉两日游。
2. 完整回复中的「查看行程地图」打开按天地图；也可先保存草稿，从行程页打开。
3. 地点名称来自行程。首次打开会在已知城市查询；城市为空时需填写后查询。只有唯一的完全同名候选才自动绑定，其余候选需核对地址后选择。
4. 休息、用餐等非具体地点可排除出地图。确认至少两个地点后，按当前顺序查询真实路线，支持步行、驾车、公交。失败路段独立提示，可仅重试失败路段。
5. 行程编辑器可上移、下移安排。更改地点名称会清除原地点绑定；路线缓存包含当天地点、顺序及出行方式，避免旧路线对应新安排。

示例行程不自动查询真实地点。每次最多显示12项安排，单个路段最多绘制2000个返回路径点；较长路线会抽稀并保留终点。当前路线缓存仅在地图打开期间保存在内存中，关闭后可重新查询。

## 数据与坐标

- 后端从明确的 `Day N`、时段标题生成 `schema_version: 1` 的行程结构，通过 `artifact` 事件单独传输并保存。结构提取不增加模型调用；旧回复保留客户端文本解析兼容。暂不声称支持任意格式的结构化提取。
- 结构只包含目的地、按天安排和附注，模型文本中的坐标不会成为地图标记。地点经实际检索、官方坐标转换和候选确认后才绑定。
- 地点由百度地点检索及官方 BD-09 → GCJ-02 转换提供。路线接口直接请求 `coord_type=gcj02`、`ret_coordtype=gcj02`、`steps_info=1`，读取实际路径点。缺少路径时不把起终点直连冒充路线。
- 沿用当前服务端 AK；地图入口独立于 MCP，需地点检索、坐标转换及相应路线 Web API 权限。AK、SK 不传给小程序，不读取设备 GPS。
- `POST /map/resolve` 批量返回地点候选及每项错误；`POST /map/routes` 返回各路段数据或错误，`segments` 可指定重试路段。均位于 `/api/v1` 下并使用当前安装的 Bearer 凭证。

## 查询耗时与部分结果

明确的本地旅行问题可直接路由到目的地助手，省去一次模型调度；完成所需业务查询后直接进入回答，省去未使用的助手总结。独立助手并行查询，单个助手最多并发3个工具；批量地图接口每个请求最多并发2项。依赖坐标或行政区代码的查询保持先后关系。

当前阶段时限：分配需求15秒、发现工具12秒、单次查询模型25秒、单项工具20秒、最终回答35秒，整次聊天保留120秒上限，小程序130秒停止等待。已完成的模型输出按短间隔合并事件，首段立即发送。已完成事件记录 `elapsed_ms`，可用于比较实测耗时；不承诺供应商实时调用的固定响应速度。

公开错误区分配置/鉴权、配额/频率、超时、网络、参数、无结果、服务不可用。错误只包含固定说明，不转发供应商异常文本、URL 或凭据。异步只读工具遇到可识别的短暂连接或服务故障最多重试一次；鉴权、配额、参数错误和工具超时不自动重试。同步工具被取消后线程仍可能运行，因此不会自动重叠重试。

部分查询失败时直接展示成功证据中的可识别地点、天气及路线事实，另列失败项，不让模型补全失败事实。未知结果结构只保留证据，不向用户直接倾倒原始 JSON。最终回答模型失败时也可回退到已查询事实。

## 断线、停止和重新生成

WebSocket 是任务的订阅连接。临时断线保留任务；每个业务事件保存到数据库后再发送，带递增 `seq`。服务端每10秒发送心跳；小程序25秒无消息会重连，自动重连最多两次，使用原请求编号、`resume=true` 与 `after_seq` 补发缺失事件，重复事件不会重复显示。

主动「停止」通过 WebSocket 取消消息及经过鉴权的 HTTP 取消接口终止后台任务，保存部分回复并标记中断。「恢复或重试」沿用请求编号，已完成任务直接回放；确已中断的任务可能重新调用模型。「重新生成」使用新请求编号，避免一直回放旧结果。

当前运行任务属于单个后端进程，部署请使用单个 Uvicorn worker。已完成内容及事件持久化；进程重启时不声称未完成计算自动恢复，连接恢复会明确提示任务中断并保留可恢复的已发送文本。多个 worker 或多实例部署需要共享任务队列和事件分发，尚未实现。最多同时运行8个聊天任务。

数据库使用新增表保存行程附属数据和事件，原会话表无需破坏性迁移；删除对话会级联删除附属记录。现有安装身份隔离继续生效。

## 验收

自动化覆盖部分成功、阶段超时、有限重试、并行结果合并、同一请求断线补发、去重、心跳、主动取消、安装间隔离、完成后数据库回放、地图坐标/路径校验、单路段重试、行程编辑后的地点失效和顺序变化。

真实地图服务权限、返回路径，以及手机微信原生地图和打开位置效果需单独验证；模拟供应商响应和页面挂载不能替代这些检查。

## 多地点与查询依据

同一时段中明确的“A & B”“A + B”会拆成分别可绑定地图的安排；“A 或 B”保留为二选一，先选安排再确认实际地点。括号内的名称、拉丁品牌中的连字符不会随意拆分；混合且/或关系保留原文，需用户编辑澄清。历史草稿拆分时保留原描述，已有地点绑定只传给名称匹配的那一项。

回复和保存的行程新增「查询依据」入口，展示本次查询的来源、时间、证据编号及实际返回字段，支持查看脱敏后的有限返回片段。依据随历史记录、断线补发和保存草稿保留。旧记录未保存依据时会明确说明，不追认过去的数字已核实。

流式展示和最终保存共用字段级检查：可识别的金额、评分、距离、耗时、线路、出口和开放时间缺少对应依据时标为待确认；用户预算和建议游览时长按计划处理。相对日期按本轮北京时间纠正，历史助手回答只保留行程结构作为上下文，不作为本次天气和价格证据。此检查不是通用语义事实核验，不能证明全部描述均准确；真实供应商调用与真机验收仍需独立完成。
